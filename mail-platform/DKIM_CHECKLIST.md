# 導入・更新後の手動対応チェックリスト

導入・更新が完了したことと、公開運用の準備が完了したことを分けて表示します。
DNSへ書き込む権限やAPI資格情報は必要ありません。DNSの登録は導入先の管理者が行います。
管理画面のダッシュボード上部に、署名対象ごとの未完了項目・DNS名・TXT値を表示します。
初回の外部ポート閉鎖、パスキー登録、明示的な公開操作は従来どおり維持します。

## 自動処理と手動対応

| 状態 | 導入・更新 | 管理者の対応 |
|---|---|---|
| DKIM鍵が不足 | root専用の保管領域にRSA2048鍵を生成し、処理を完了 | 表示された公開TXTをDNSへ登録 |
| TXT未登録・不一致・伝播待ち・照会障害 | 未完了項目を記録し、処理を完了 | DNS名と値を確認し、再照合 |
| 一致する重複bool設定 | 対象3項目だけ重複を除去して構文・実効値を確認 | 通常は不要 |
| 相反する重複設定、独自map/複数selector等 | 既存設定を保持し、要確認として完了 | 対象範囲を確認して設定を整理 |
| DNS一致・安全な署名設定 | 新規鍵を既知パスへ原子的に配置 | 定期確認だけで一致した場合は、下記コマンドで有効化 |
| 過去の未完了生成鍵を検出（設定変更前） | 上書きせず要確認として完了 | 保存された失敗記録を調査 |
| 今回の変更中断、未知の書換え、変更結果不明 | 成功とは扱わず停止・条件付き復旧 | 保存された失敗記録を調査 |

チェックは現在のDKIM設定からドメイン・selectorを取得します。既存の鍵を作り直しません。
公開TXTが一致するまで、新しく生成した鍵は署名用パスへ配置しません。
`check_pubkey=true`、`allow_pubkey_mismatch=false`、`sign_inbound=false`と署名ドメインの選択を確認できない場合も、新しい鍵は有効化しません。
既存の独自設定を初期値へ置換する処理はありません。

## DNS登録後

管理画面に表示されたDNS名・種別TXT・公開鍵の値をDNS管理画面へ登録します。
既存TXTを確認せず上書きしないでください。秘密鍵をDNSへ登録してはいけません。
GoogleとCloudflareの公開DNS応答を照合します。二者の応答が一致しない間は伝播待ちです。
DNS照会には実行予算を設け、到達できない環境でも導入・更新を継続します。

```sh
# 公開DNSと既存鍵の照合だけ。DNS・鍵の配置を変更しない。
sudo python3 -I -S -B /usr/local/lib/mail-platform-update/entry.py dkim-check

# 再照合し、条件が揃った不足鍵を有効化。DNSへの書込みやメール送信はない。
sudo python3 -I -S -B /usr/local/lib/mail-platform-update/entry.py dkim-apply
```

更新確認timerも読取り照合を行います。初回導入で公開前のtimerが停止中の場合は、上の手動確認を使います。
結果は古くなれば「確認結果が古い」、取得に失敗すれば「取得できません」と表示し、未確認を緑にしません。
すべての対象鍵・公開DNS・署名設定を確認した時だけ、DKIM確認完了になります。
この緑表示はDKIMの範囲です。MX、SPF、DMARC、逆引き、VPSのポート許可、TLS、送受信先の判定まで確認済みとする表示ではありません。
初期公開・証明書・運用確認は[初期設定](INITIAL_SETUP.md)・[証明書](CERTIFICATES.md)・[導入条件](INSTALLATION.md)も確認してください。

## 保持・復旧

既存の鍵・DNS・メール・UIDL・DB・通知設定・履歴を保持します。
設定の変更前後と生成鍵の公開部分を記録し、今回変更したものと完全一致する場合だけ復旧します。
復旧で新しい鍵を署名用パスから外しても、root専用の保管領域には保持します。
同じ鍵をDNS登録や続行に再利用でき、無条件の再生成や削除は行いません。
実行中のRspamdへ設定変更を反映する場合は、HUP受付準備・masterの同一性を確認してreloadします。
reloadの結果不明では追加reloadを自動実行しません。
