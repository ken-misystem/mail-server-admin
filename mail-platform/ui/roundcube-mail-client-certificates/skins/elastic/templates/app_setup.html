メールアプリ登録方法

メールアプリには、本人の端末証明書とアプリ用パスワードを設定します。このページを別タブに残し、準備 → 証明書の取込み → 受信・送信設定の順に進めてください。

Webだけで使う場合は、Roundcubeへ戻る。Web利用には端末証明書もアプリ用パスワードも不要です。

メールアプリに入力する接続情報

受信・送信共通のサーバー名：mx.mi-sys.jp

本人のユーザー名：Roundcubeにログインしている本人のメールアドレス

受信・送信の両方に、上のユーザー名と同じ本人のアプリ用パスワードを入力します。別名・転送先や他人のアカウントを入力しないでください。

受信はIMAPまたはPOPのどちらかを選択。送信はSMTPを設定します。

587で「SSL/TLS」、993・995で「STARTTLS」を選ばないでください。「暗号化なし」「証明書のエラーを無視」は使いません。465は専用の旧SMTP認証ID用で、この手順の代わりには使えません。

POPを使う場合は「サーバーにメッセージのコピーを残す」を有効にしてください。取得後に削除する設定では、Roundcubeや別の端末からそのメールを読めなくなります。

最初の準備：3つの秘密を使い分ける

用意するもの使う場所
Roundcubeのログインパスワード／パスキーWebのログイン・本人確認。メールアプリのパスワード欄へ流用しません。
アプリ用パスワードメールアプリの受信・送信のパスワード欄。
P12ファイル＋P12保護パスワード端末証明書を取り込むとき。保護パスワードは受信・送信のパスワード欄へ入力しません。
  1. パスキーを登録・管理（別タブ）を開き、本人のパスキーを登録します。証明書の発行時に本人確認を行います。
  2. アプリ用パスワード（別タブ）で、端末名を付けて発行します。一度だけ表示される値をパスワード管理アプリへ保存します。端末ごとに分けると、紛失時にその端末だけ失効できます。
  3. 端末証明書（別タブ）で本人のアカウントを確認し、端末名と16〜128文字の空白を含まない半角英数字・記号のP12保護パスワードを入力して「発行する」を押します。保護パスワードも安全に保管します。
  4. 発行した画面の「P12をダウンロード」を押し、.p12を保存します。取得は一度だけ・最大5分以内です。取得完了前に画面移動・再読み込みをしないでください。取得できなくなった証明書は失効し、再発行します。
  5. 設定する端末へP12を安全に渡し、下のアプリ別の手順へ進みます。チャット・メールへの添付や第三者との共有は避け、端末内の取込み後は不要なダウンロードコピーを削除します。端末を追加するときは別の証明書を発行します。

この証明書は接続時の本人確認（TLSクライアント証明書）用です。メール本文の署名・暗号化を行うS/MIMEの設定ではありません。S/MIME欄にだけ登録しても接続設定は完了しません。

FairEmailの設定

  1. 公式配布元からFairEmailを導入します。Androidの設定で「証明書をインストール」→VPNとアプリ用を開き、本人のP12を選びます。画面の名称は端末ごとに異なります。P12保護パスワードを入力し、端末名など識別できる名前で保存します。「CA証明書」やWi-Fi専用証明書として取り込まないでください。
  2. FairEmailの「設定」→「手動セットアップ」→「アカウント」から追加します。受信はIMAP、サーバーmx.mi-sys.jp、993、SSL/TLS、本人のユーザー名、アプリ用パスワードを設定します。FairEmailはIMAPを使用してください。確認した1.2340のPOP設定にはクライアント証明書の指定がなく、このサーバーの995番用の設定はできません。POPを使う場合はBetterbirdまたはThunderbirdを利用してください。
  3. 同じ受信設定内のクライアント証明書（Client certificate）ボタンから、取り込んだ本人証明書を選び、Androidの利用確認を許可します。項目が折りたたまれている場合は詳細設定を開きます。パスワード欄も入力したままにします。
  4. 「手動セットアップ」→「個人情報／Identities（送信元）」で、この受信アカウントに対応する送信設定を追加します。送信元は本人の許可されたアドレスにし、SMTPmx.mi-sys.jp、587、STARTTLS、ユーザー名、アプリ用パスワードを入力します。
  5. 送信側のクライアント証明書にも、受信側と同じ証明書を選びます。受信側だけの選択では送信設定が完了しません。証明書エラーの無視は有効にしません。保存後、受信フォルダーが表示されることを確認します。

公式：対応する認証方式・クライアント証明書 ／ 手動設定 ／ 配布元

Betterbirdの設定

BetterbirdはThunderbird ESRと互換のある派生版です。P12の取込み・受信・送信は、次のThunderbirdの図解手順で設定します。OSの証明書保管庫へ入れるだけで終わらず、Betterbird自身の証明書マネージャーで本人証明書があることを確認してください。

  1. Betterbird公式配布元から使用OSの版を導入します。
  2. Betterbirdの「設定」→「プライバシーとセキュリティ」→証明書の管理を開き、P12を「あなたの証明書」へ取り込みます。
  3. 受信993・SSL/TLS、送信587・STARTTLS、通常のパスワード認証を指定します。パスワードはアプリ用パスワードです。接続時に本人証明書を選びます。

公式：Thunderbird ESRとの互換性・対応OS

Thunderbirdの設定（Betterbirdも共通）

  1. 公式サイトから導入します。「設定」→「プライバシーとセキュリティ」→「証明書」→「証明書を管理」を開きます。
  2. 「あなたの証明書」タブで「インポート」を押し、P12ファイルを選びます。発行時に自分で決めたP12保護パスワードを入力します。本人の証明書が一覧に現れたことを確認します。「認証局証明書」タブへ入れる操作ではありません。
  3. 「アカウント設定」からメールアカウントを追加し、本人の表示名・メールアドレス・アプリ用パスワードを入力します。「手動設定」で受信をIMAP、サーバーmx.mi-sys.jp、993、SSL/TLS、認証方式「通常のパスワード認証」、本人のユーザー名にします。POPなら995・SSL/TLSです。
  4. 送信SMTPはmx.mi-sys.jp、587、STARTTLS、通常のパスワード認証、同じユーザー名にします。「送信（SMTP）サーバー」の設定と、アカウントに割り当てた送信サーバーが一致することも確認します。
  5. 接続時に「ユーザー識別の要求」などの証明書選択画面が出たら、接続先がmx.mi-sys.jpであることを確認し、このアカウントの端末証明書を選択します。受信と送信でそれぞれ求められた場合は同じ本人証明書を選びます。保存されている選択によっては再表示されません。
  6. パスワードを求められた場合は、アプリ用パスワードを入力します。証明書を選んでもパスワード認証は必要です。受信フォルダー表示を確認します。

認証方式を「TLS証明書／外部証明書」へ変える手順ではありません。接続用証明書を選び、パスワード認証も使います。S/MIMEの署名・暗号化用の証明書選択だけでは完了しません。

公式：手動アカウント設定 ／ 証明書設定の公開実装 ／ 接続用証明書の選択に関する開発記録

Apple「メール」の設定

Macでは標準の「メール」にTLS証明書の指定機能があります。Betterbird / Thunderbirdを使う場合は上の手順で設定してください。

  1. 「キーチェーンアクセス」を開き、本人の「ログイン」キーチェーンを選び、「ファイル」→「読み込む」でP12を取り込みます。P12保護パスワードを入力し、「自分の証明書」で証明書に秘密鍵が付いていることを確認します。
  2. 「メール」→「アカウントを追加」→「その他のメールアカウント」で、本人のアドレスとアプリ用パスワードを入力します。手動入力が必要な場合は受信IMAP・送信SMTPともmx.mi-sys.jpにします。
  3. 「メール」→「設定」→「アカウント」→対象アカウント→「サーバ設定」を開きます。受信の「接続設定を自動的に管理」を外し、ポート993・TLS/SSLを使用・認証はパスワードにします。ユーザー名とアプリ用パスワードを確認します。
  4. 受信の「詳細なIMAP設定」（POPなら「詳細なPOP設定」）を開き、「TLS証明書」で本人証明書を選びます。
  5. 送信用アカウントから「SMTPサーバリストを編集」を開きます。対象SMTPの自動管理を外し、587・TLS/SSLを使用・パスワード認証を設定します。587はSTARTTLSで接続する設定です。送信の「詳細」→「TLS証明書」にも同じ本人証明書を選びます。
  6. 保存し、キーチェーンの秘密鍵利用確認が出たら「メール」からの要求であることを確認して許可します。「安全でない認証を許可」や証明書エラーの無視は有効にしません。受信フォルダーが表示されることを確認します。

Apple公式：キーチェーンへの読み込み ／ 受信・サーバ設定 ／ 送信サーバ設定とTLS証明書

K-9 Mailの設定

公式6.400マニュアルで、受信・送信のTLSクライアント証明書選択を確認しています。Thunderbird for Androidについては、この旧版手順と現行画面の一致を確認していないため、同一手順で設定できるとは扱いません。Androidの第一推奨はFairEmailです。

  1. Androidの「VPNとアプリ用」の証明書として本人のP12を取り込みます。P12保護パスワードを使い、識別できる名前を付けます。
  2. K-9 Mailでアカウントを追加し、手動設定でIMAPを選択します。受信mx.mi-sys.jp、993・SSL/TLS、本人のユーザー名とアプリ用パスワードを入力します。
  3. 受信設定のClient certificateで本人の証明書を選びます。認証は通常のパスワード認証（Normal password）を使います。証明書だけで認証する方式は選びません。
  4. 送信設定をmx.mi-sys.jp、587・STARTTLSにし、認証を必須にして同じユーザー名とアプリ用パスワードを設定します。送信側のClient certificateも同じ本人証明書にします。
  5. 保存後に受信フォルダーを確認します。現行画面で証明書選択とパスワードを同時設定できない場合は、FairEmailまたはRoundcubeを使用してください。

公式：IMAP設定 ／ 送信設定

Roundcubeと、証明書対応候補Preside

iPhone / iPadではSafariからRoundcubeを使う方法を案内します。端末証明書の取込みは不要です。iPhone標準「メール」で、このサーバーの受信・送信にTLSクライアント証明書とパスワードを併用する手順は確認できていません。

Presideは公式ガイドでPKCS#12取込みとアカウントへのSSLクライアント証明書割当てを確認できた候補です。ただし公式ガイド自身が古いと明記しており、SMTP 587のSTARTTLS設定・証明書併用の現行手順は未確認です。このサーバーで送受信できる確認済みアプリとしては案内しません。

公式資料で確認できた証明書の登録手順

  1. 本人のP12とP12保護パスワードを用意します。公式ガイドの方法は、PCのiTunesファイル共有でPresideへP12を渡す操作です。現在の端末で同じ導線がない場合は、現行アプリのヘルプを確認し、未確認のプロファイルやCAを追加しないでください。
  2. Presideの「More」→「Tools」→「Advanced Tools」→「Certificates」から追加（Add）を開きます。「Import Certificate」でP12を選択し、P12保護パスワードを入力して「Save」で取り込みます。
  3. 対象アカウントの詳細設定「Communication」→「Client certificate」へ本人の証明書を割り当てます。「Ignore certificate errors」はオフにします。

この3段階は証明書機能の説明です。送信設定が未確認のため、ここだけで登録完了とは扱いません。587・STARTTLSと本人証明書を併用できる手順が確認できるまではRoundcubeをご利用ください。465・暗号化なしへの変更で回避しないでください。

公式：Presideガイド（Certificates / Import Certificate / Communication） ／ 製品情報

対応していない・対応を確認できないアプリについて

クライアント証明書方式に対応しないメールアプリでは利用できません。受信・送信の両方で本人証明書を提示でき、パスワード認証も併用できる必要があります。対応アプリを導入するか、Roundcubeでご利用ください。S/MIME対応、Exchangeの証明書ログイン、サーバー証明書の確認だけでは、この条件を満たしません。

接続できないとき・端末を失くしたとき

症状確認する項目
P12の取込みに失敗使う値はP12保護パスワードです。P12に秘密鍵が含まれていることを確認します。ファイルがない・取得期限が切れた・保護パスワードを忘れた場合は失効して再発行します。
接続直後に切断 / certificate required有効な本人証明書を受信・送信の両方に選択したか確認します。端末へインストールしただけで、アプリ側で選択していない状態は未完了です。
パスワードエラー本人のユーザー名、証明書の所有アカウント、アプリ用パスワードの発行アカウントを一致させます。Webログイン用やP12保護用のパスワードを入力していないか確認します。
受信できるが送信できない送信側の証明書選択・587・STARTTLS・認証・許可された本人送信元を確認します。Thunderbird系はアカウントに割り当てたSMTPも確認します。
証明書名不一致 / 不明なサーバーサーバー名はmx.mi-sys.jpです。IPアドレスや旧サーバー名を使わず、警告は無視しないで管理者に知らせてください。
上限到達などの一時拒否（451）送信アプリの保留・再送状態を確認します。送信済みか不明なメールを手動で何度も送り直さず、管理者へ発生時刻とエラーを連絡してください。
端末紛失・譲渡・証明書更新Roundcubeの「端末証明書」と「アプリ用パスワード」で該当端末を失効します。新しい端末・更新には新しい証明書とアプリ用パスワードを設定してください。

解決しない場合は、アプリ名・OS・エラー・発生時刻を管理者へ連絡してください。パスワード、P12、秘密鍵は連絡に添付しません。
